## Disclaimer

> ⚠️ **This is a research benchmark on synthetic patient data. It is NOT a clinical tool and must
> NOT be used to inform any medical decision.** The DDXPlus dataset is fully synthetic — cases are
> generated by a probabilistic simulator, not drawn from real patient records. All results describe
> model behaviour on a controlled benchmark and carry no implications for real-world clinical
> performance or safety.

---

## TL;DR

Claude Sonnet 4.6 achieved **52.8% top-1 accuracy** and **97.2% top-5 accuracy** across 36
evaluated cases from the DDXPlus test split. The dominant failure mode is *specificity bias*: the
model picks a more mechanistically precise diagnosis (e.g., Influenza) when the benchmark's ground
truth is a broader umbrella term (e.g., URTI), with the correct answer consistently ranking 2nd–3rd.
The single hard miss — where the correct answer fell outside the top 5 — is arguably a benchmark
labelling error rather than a genuine model failure.

## Key Findings

### 1. Specificity bias dominates the soft misses (44%)

Of 16 soft misses (top-1 wrong, top-5 correct), **7 cases (44%)** follow the same pattern: the
model ranks a more specific diagnosis first and places the benchmark's preferred umbrella term at
rank 2–3. The canonical example is **Case 4**: a 70-year-old female presenting with cough whose
GT label is `URTI`, but whose symptom cluster (cough, muscle pain, possible fever) is a textbook
Influenza presentation. The model ranked `Influenza` first and `URTI` third — a clinically
defensible choice that the benchmark scores as a miss.

Other examples of the same pattern: Influenza → URTI (×3), Acute rhinosinusitis → URTI (×3),
Acute COPD exacerbation / infection → Bronchitis. In all cases, the model
knew the correct answer; it simply weighted a more specific alternative more highly.

This is not random error. It is a systematic calibration bias toward mechanistic specificity that
any top-k evaluation framework will penalise.

### 2. The only hard miss may be a benchmark labelling error

Across 36 cases, the GT pathology fell outside the model's top 5 exactly **once**: **Case 1**,
a 2-year-old male where the model's top prediction was `Bronchiolitis` but the GT label was
`Bronchitis` (GT rank: 9, MRR: 0.111).

Three observations make this the most interesting result in the dataset:

- **Bronchiolitis is the textbook diagnosis for children under 2.** It is the most common lower
  respiratory tract infection in that age group. The model applied a well-established, age-stratified
  clinical prior.
- **DDXPlus's 49-condition vocabulary does not include Bronchiolitis.** The benchmark's label set
  omits the age-appropriate condition entirely, making it structurally impossible for the model to
  be rewarded for age-stratified reasoning.
- **The model still found `Bronchitis` at rank 9** — it wasn't blind to the label, it just
  correctly deprioritised it given the patient's age.

This case exposes a known limitation of DDXPlus: its fixed 49-pathology vocabulary was not designed
to capture age-stratified clinical reasoning.

### 3. Top-5 accuracy is near-perfect

**97.2% top-5 accuracy** (35 of 36 cases) means the model almost never failed to *generate* the
correct diagnosis — the knowledge was consistently present in its output. In a clinical
decision-support context where a clinician reviews a full differential list rather than a single
top pick, this would translate to missing the correct diagnosis on roughly 1 in 36 presentations.
The remaining research problem is ranking: getting the correct answer to position 1 rather than
positions 2–4.

## Methodology

### Dataset: DDXPlus

DDXPlus (Tchango et al., 2022) is a large-scale synthetic differential diagnosis dataset
containing ~304,000 simulated patient cases across **49 pathologies**. Each case specifies patient
age, sex, an initial complaint code, and a set of binary/multi-value symptom evidence codes. Each
case also includes a ground-truth single confirmed pathology and a probability-weighted differential
diagnosis list. The dataset is released under **CC BY 4.0**.

This evaluation used the `test` split with a limit of 50 cases. Evidence codes were decoded to
human-readable English using the dataset's `release_evidences.json` metadata file.

### Model

**claude-sonnet-4-6** via the Claude Agent SDK, authenticated with a Pro subscription OAuth token
(no paid API credits). Model parameters were not modified; the API's defaults were used throughout.
Each case is an independent, stateless query — no conversation history is shared between cases.

### Prompt design

Each case was formatted as a plain-English clinical vignette:

```
Patient: {age}-year-old {sex}.
Initial complaint: {decoded_initial_evidence}
Reported symptoms and history: {decoded_evidence_list}
```

The system prompt provided the complete 49-pathology canonical name list and required:
- A ranked differential of up to 10 entries, each with an exact canonical pathology name, a
  probability (0–1), and one sentence of clinical reasoning
- Strict JSON output — no markdown fences, no preamble
- Top diagnosis matching the first differential entry

Restricting the model to exact canonical names removes name-normalisation ambiguity as a
confounding variable. The system prompt was held constant across all 36 evaluated cases (no
few-shot examples, no chain-of-thought instruction).

### Scoring and normalisation

Model output pathology strings are normalised to canonical names via a three-stage fallback:

1. **Exact match** (case-insensitive)
2. **Substring match** in either direction
3. **Fuzzy match** via `difflib.get_close_matches` with cutoff 0.7

A normalisation failure (no match at any stage) causes that entry to be excluded from
precision/recall calculations; it does not count as a top-1 or top-5 hit.

Five metrics are computed per case: **Top-1 accuracy** (exact match at rank 1),
**Top-5 accuracy** (match within top 5), **Mean Reciprocal Rank** (1/rank, 0 if absent),
**Differential Precision** (fraction of predicted pathologies in GT differential set),
**Differential Recall** (fraction of GT differential pathologies appearing in predictions).

### Eval pipeline

Cases are evaluated sequentially via `asyncio`. Per-case results are streamed to a JSONL file
as they complete (one JSON object per line) so that partial results survive a crashed run. A
summary JSON is written at the end. Total wall time for 36 cases: **2,911 seconds (~48 minutes)**
at an average of ~27 seconds per case.

## Reproducing the Results

### Prerequisites

- Python 3.11+
- A Claude **Pro subscription** (the eval uses the Claude Agent SDK OAuth flow, not paid API
  credits)
- A `CLAUDE_CODE_OAUTH_TOKEN` from your Claude Code session

### Steps

```bash
# 1. Clone the repository
git clone https://github.com/amahamu1-art/diffdx.git
cd diffdx

# 2. Create and activate a virtual environment
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 3. Install dependencies
pip install claude-agent-sdk datasets python-dotenv tqdm pandas matplotlib

# 4. Add your OAuth token to a .env file
echo "CLAUDE_CODE_OAUTH_TOKEN=your_token_here" > .env

# 5. Run the evaluation
python scripts/run_eval.py --n 50 --model sonnet --split test
```

Available model aliases: `sonnet` → `claude-sonnet-4-6`, `opus` → `claude-opus-4-7`,
`haiku` → `claude-haiku-4-5-20251001`.

**Runtime estimate:** ~27 seconds per case under normal conditions. 50 cases takes approximately
**30–50 minutes** of wall time and consumes a meaningful fraction of a Pro subscription session
quota. Rate limiting kicks in around case 35–40 in a single session; run in batches of ≤30 or
add `--n 30` for reliable completion.

**Output files** are written to `results/` automatically:
- `results/eval_{model}_{timestamp}.jsonl` — per-case metrics, latency, predictions
- `results/summary_{model}_{timestamp}.json` — aggregate metrics and run metadata

## Limitations

- **Synthetic data only.** DDXPlus cases are generated by a probabilistic simulator. Symptom
  co-occurrence patterns reflect the simulator's priors, not real clinical presentations. Results
  on synthetic data do not generalise to real patient data.
- **n = 36 due to rate-limiting.** 14 of 50 cases (28%) were lost to Pro subscription session
  throttling. The error pattern was non-random (cases 36–49), which may introduce selection bias
  in the aggregate metrics.
- **Single model, single prompt strategy.** No comparison to other models, no prompt ablation,
  no few-shot or chain-of-thought variants tested.
- **Fuzzy normalisation is imperfect.** The three-stage normalisation pipeline can produce false
  matches (e.g., substring matches between short condition names) or false non-matches for unusual
  model phrasings.
- **No specialist baseline.** There is no human-expert or specialist-physician comparison. Reported
  accuracy figures are in isolation.
- **49-pathology vocabulary is restrictive.** DDXPlus's fixed label set excludes common conditions
  (e.g., Bronchiolitis) and does not capture age-stratified diagnoses, which biases top-1 accuracy
  downward for cases where the clinically correct diagnosis is outside the vocabulary.

## Future Work

- **Multi-model comparison.** Run identical cases through `claude-opus-4-7`, `claude-haiku-4-5`,
  and an open-weight medical model (e.g., BioMistral-7B) to produce a head-to-head accuracy table.
- **Prompt strategy ablation.** Compare zero-shot (current), chain-of-thought, and structured
  reasoning (step-by-step differential construction) to measure whether explicit reasoning improves
  top-1 accuracy without degrading top-5.
- **Larger n with checkpointing and backoff.** Implement exponential retry on rate-limit errors
  and mid-run checkpointing by case index, enabling reliable 200–500 case evaluations in a single
  script run.
- **Stratified analysis.** Break results down by age group, sex, and pathology class to identify
  whether specificity bias is uniform or concentrated in specific presentation types.
- **Real-world clinical case validation.** Under appropriate IRB oversight and data use agreements,
  evaluate on a de-identified real-patient dataset to test whether synthetic-data results generalise.
